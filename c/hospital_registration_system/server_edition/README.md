# 医院挂号系统 · 服务器版

Windows 上的单服务器、多客户端演示。服务器进程维护一份按医生组织的邻接表，也由它读写本地二进制数据。终端版和 EasyX 版通过 TCP 使用同一套服务。可以混合打开多个客户端，让不同患者、医生同时登录操作。

## 项目结构

| 目录 | 内容 |
| --- | --- |
| `server/` | C 语言服务器，邻接表和数据读写代码 |
| `server/data/` | 本地数据目录，离线工具可从示例 TXT 创建两名虚构医生和两个科室 |
| `clients/console/` | C 语言终端客户端 |
| `clients/easyx/` | C 风格 C++ 的 EasyX 客户端。其 `resource/` 存放菜单图和可选资料卡 |
| `clients/common/` | 两个客户端共用的网络请求、登录输入和就诊须知（`resource/rules.txt`） |
| `clients/local_ai/` | 客户端可选的本地 Python AI 脚本 |
| `shared/` | 客户端与服务器共用的 TCP 协议定义 |
| `tools/` | C 语言离线数据工具、科室和医生的 TXT 示例 |
| `tests/` | 使用临时数据的 TCP 联调和数据工具测试 |

## 编译

在 CMD 中进入项目根目录（包含 `build.cmd` 的目录）。编译环境是 **MSYS2 MinGW-w64 GCC/G++ 16.2.0，64 位**，以及 64 位 MinGW 版 EasyX。如果编译器或 EasyX 的安装路径与下方示例不同，请按实际路径修改变量。

```bat
set "MINGW_BIN=D:\msys64\mingw64\bin"
set "EASYX_ROOT=D:\EasyX"
chcp 936
build.cmd
```

脚本把服务器、终端版、EasyX 版和数据工具分别编译到自己的目录。源文件中的中文使用 GBK。服务器和终端客户端使用 GCC，EasyX 客户端使用 G++。

## 首次启动

1. 从 GitHub 下载并解压后，找到包含 `build.cmd` 的项目目录，按上面的[编译步骤](#编译)生成 EXE。
2. 双击 `tools\data_tool.exe`。先输入 `1` 选择科室表，再输入 `2` 导入 TXT，按 Enter 使用默认文件。
3. 回到选表菜单后，输入 `2` 选择医生表，再输入 `2` 导入 TXT，按 Enter 使用默认文件。导入成功后输入 `0` 退出工具。
4. 双击 `server\hospital_server.exe`。看到 `Hospital server listening on 127.0.0.1:8765` 后，保持服务器窗口打开。
5. 双击 `clients\console\hospital_console.exe` 启动终端版，或双击 `clients\easyx\hospital_easyx.exe` 启动图形版。患者先注册再登录，医生可以使用下方的演示账号。

## 在一台电脑上多开

完成首次初始化后，每次先启动服务器，再打开所需的客户端。也可以在包含 `build.cmd` 的目录下用 CMD 启动。

```bat
start "Hospital Server" server\hospital_server.exe
```

看到监听提示后，再启动需要的客户端。

```bat
start "Patient Console" clients\console\hospital_console.exe
start "Patient EasyX" clients\easyx\hospital_easyx.exe
start "Doctor Console" clients\console\hospital_console.exe
```

不同患者应分别注册账号，例如 `100000001`、`100000002`。医生可以用下列虚构账号登录。

| 工号 | 演示密码 | 科室和排班 |
| --- | --- | --- |
| 100001 | `demo101` | 全科，00:00–24:00，初始上午和下午各 5 个号 |
| 200001 | `demo201` | 骨科，08:00–17:00，初始上午和下午各 10 个号 |

同一账号同一时间只能有一个登录连接。退出菜单会退出登录，但可以在同一个客户端切换用户，其他客户端继续工作。

要观察多个用户争抢号源，可以让医生把全科未来时段的上限设为 1，再让两名患者选择同一天的同一时段。谁的请求先提交，谁拿到占位。医生叫号只读取自己当前可就诊时段的队列，因此演示完整叫号流程应挂当天当前时段。

## 在局域网内运行

启动参数为 `[IPv4] [端口]`。服务器参数是本机要监听的地址，客户端参数是远端服务器的地址。例如服务器网卡地址是 `192.168.1.25`：

```bat
server\hospital_server.exe 192.168.1.25 8765
```

在另一台电脑上使用同一版本的客户端：

```bat
clients\console\hospital_console.exe 192.168.1.25 8765
clients\easyx\hospital_easyx.exe 192.168.1.25 8765
```

可在 `shared/protocol.h` 顶部改默认地址和端口，修改后重新编译。服务器应允许选定端口的 TCP 入站连接，客户端无需携带服务器数据目录。预约日期和截止时间以服务器当地时间为准；建议演示时各电脑采用同一时区。当前是明文 TCP 演示协议，适合本机和可信局域网的虚构数据，默认只监听回环地址。

## 服务如何处理请求

- 主线程用 Winsock 的 `select` 同时照看多个连接。请求收齐后依次执行，数据库写入、检查余号和插入节点都在这一条业务执行路径上。客户端等输入或长时间停在菜单时不会占用这条执行路径。
- 每个连接有独立的登录角色和当前叫号。服务器按连接判断身份。患者只能处理自己的订单，医生只能操作自己的号源和叫号队列。
- 报文由固定长度的请求和带长度的响应组成，支持 TCP 分段收发。客户端拿到的是科室、日期、自己历史记录等页面数据。提交时由服务器重新检查时段、号源、付款截止和操作权限。
- 预约按日期、时段、创建时间有序入链。过期检查由服务器定期执行。退出或断开连接会释放该患者的未付款占位；医生断线后，未结束的叫号按时段情况回到队列或完成。
- 服务器的文件锁防止第二个进程打开同一个数据目录。预约与付款继续使用二进制文件及付款恢复日志。关闭服务器后再备份整个 `server/data`。该目录用于保存本机数据，示例配置在 `tools/*.txt`，可以重新生成数据库。
- 服务器最多同时接收 64 个连接。无操作的未登录连接约 2 分钟后关闭，已登录连接约 1 小时后关闭。服务器关闭或连接超时后，重新打开客户端即可重新登录。
- 日志只打印到服务器终端，包括连接、来源 IP、请求名、处理结果和记录数。密码和完整业务报文不会写入日志。

## 就诊须知

两个客户端读取同一份 `clients/common/resource/rules.txt`。用 GBK 编码修改该文件，再重新打开客户端里的就诊须知即可。复制客户端到其他电脑时，保留客户端目录与 `common/resource` 的相对位置。

## 离线数据工具

关闭服务器后，从 `tools` 双击 `data_tool.exe`，或在该目录运行 `data_tool.exe`。工具通过相邻的 `server` 目录定位 `server/data`，直接操作二进制文件。它与服务器共用数据锁。若上一次付款尚未完成恢复，先启动并退出服务器，再运行工具。建议清空或同步前备份整个 `server/data`。

进入工具后先选择一张表，再选择操作。

| 选项 | 操作 |
| --- | --- |
| 1 · Show all | 显示该表的全部记录，隐藏密码和密码摘要 |
| 2 · Import TXT | 追加 TXT 中的新主键。表中已有的记录保持原样，文件中重复的主键以第一次出现为准，并报告跳过数量 |
| 3 · Edit one | 输入主键，再输入修改后的整行，原主键须保留。医生或患者密码字段填 `-` 可保留原密码 |
| 4 · Delete one | 按主键删除一条记录 |
| 5 · Clear | 清空选中表，需要输入 `YES` |
| 6 · Sync TXT | 将选中表整体替换为 TXT 中的内容，需要输入 `YES`。文件内重复主键以第一次出现为准。遇到格式错误或引用冲突会保留原表 |

TXT 用 GBK 保存，每行一条，无表头，字段以空格或 Tab 分隔，文本字段内不填空白。提示文件名时直接按 Enter 使用所选表对应的默认 TXT。相对文件名从 `tools` 目录查找，也支持绝对路径。首次初始化时，依次选科室表 `1`、追加导入 `2`，按 Enter 读取默认文件。再选医生表 `2`、追加导入 `2`，按 Enter。输入 `0` 退出工具，然后启动服务器。两份演示 TXT 都在 `tools`。

| TXT | 每行字段顺序 |
| --- | --- |
| `departments.txt` | `科室ID 名称 位置 简介` |
| `doctors.txt` | `工号 科室ID 姓名 性别 职称 费用 密码 上班小时 下班小时 上午上限 下午上限` |
| `patients.txt` | `患者账号 姓名 性别 生日YYYYMMDD 电话 密码` |
| `appointments.txt` | `单号 患者账号 医生工号 就诊日期时间戳 时段 状态 创建时间戳` |
| `payments.txt` | `流水号 挂号单号 金额 支付时间戳` |

性别和时段使用 0 或 1。生日未知时填 0，就诊日期使用服务器当地零点的 Unix 秒时间戳。默认 TXT 只有科室和医生的演示文件，其他表按需自行创建。医生或患者的导入密码请用本地私有 TXT 保存，例如 `doctors.local.txt`。

工具会检查科室、医生、患者、挂号和付款的关联，不自动级联删除。新建已缴费的历史数据时，可先导入状态 4 的挂号，再导入流水，最后单条改为目标状态。删除仍有引用的数据前，请先处理关联表。例如，清空含有效付款预约的测试数据时，先将有关预约改为作废，再清空付款和挂号表。

## 可选的 AI 助手

两种客户端都支持本地启动 Python AI 助手。患者进入 AI 菜单时，客户端先向服务器询问当前会话是否获准，获准后在客户端电脑运行脚本。提示词、对话和模型密钥留给客户端的 Python 进程及其所配置的模型服务，挂号服务器不接收它们。

在客户端电脑安装 Python 3.10+ 和依赖，再复制配置模板。

```bat
python -m pip install openai python-dotenv
copy clients\local_ai\.env.example clients\local_ai\.env
```

编辑 `clients\local_ai\.env` 填入自己的密钥。DeepSeek 使用 `DEEPSEEK_API_KEY`。改用 OpenAI 时，将 `AI_PROVIDER` 设置为 `openai`，并填写 `OPENAI_API_KEY` 和 `AI_MODEL`。运行客户端的环境应能找到 `python`。登录限制作用于客户端的 AI 菜单，手动运行本地脚本由本机自行控制。
